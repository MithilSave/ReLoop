# 14 — Glossary, Assumptions and Open Questions

## 1. Participants
| Term | Definition |
|---|---|
| Generator | Household, society, commercial or institutional source of plastic waste (operational role) |
| Collector | Commercial collection and transport business (operational role). Receives no loyalty points |
| Recycler / PWP | Registered Plastic Waste Processor that receives and processes plastic (operational role) |
| NGO | Independent verification partner with read-only access to operational data |
| EPR company / PIBO | Producer, Importer or Brand Owner with EPR obligations; ReLoop's corporate customer |

## 2. EPR terminology
| Term | Meaning |
|---|---|
| EPR | Extended Producer Responsibility: obligated entities are responsible for the end-of-life of their packaging |
| PWM Rules | Plastic Waste Management Rules, 2016, as amended (08 §1) |
| CPCB EPR portal | Centralised online system for plastic packaging EPR registration, returns and certificates |
| EPR certificate | Statutory certificate generated by a registered PWP on the CPCB portal. **Not issued by ReLoop** |
| Certificate reference | ReLoop's record of a certificate number entered by the recycler |
| Packaging category I–IV | Categories of plastic packaging under the EPR guidelines (08 §4) |
| Eligible kg | Recycler-declared processed kg it considers attributable to EPR certificates |
| Allocation | Ledger entry assigning eligible kg to one EPR client |
| SPCB / MPCB | State Pollution Control Board; Maharashtra's is MPCB |

## 3. Product and technical terms
| Term | Meaning |
|---|---|
| Waste batch | One generator listing; the unit of traceability with a unique code and QR |
| Material passport | Read-only, complete history of a batch (05 §4.10) |
| Processing run / record | One recycler processing event with measured input, output and residue |
| Lineage | The links from batch to receipt to processing inputs to run to certificate and allocation |
| Consignment | One vehicle trip grouping several batches without merging them |
| Aggregation plan | A proposed set of existing listings to meet a recycler demand; it requires human acceptance |
| Landed cost per usable kg | Total expected procurement and logistics cost ÷ expected usable kg |
| Processing yield | Measured output ÷ measured input × 100 |
| Mass balance / unaccounted kg | input − output − residue |
| Confirmed supply | kg in LISTED/ASSIGNED batches (declared estimates of real, listed material) |
| Predicted supply | Forecast kg. Never inventory |
| Supplier performance indicator | A rule-based metric shown with its transaction count n |
| Modular monolith | One deployable with strict internal module boundaries |
| JWT / OTP / RLS / PITR | JSON Web Token; one-time password; row-level security; point-in-time recovery |

## 5. Assumptions (validate before going live)
| ID | Assumption | Default chosen |
|---|---|---|
| A-01 | Single city (Mumbai) pilot | `city_id='MUM'` |
| A-02 | Households act as single-member generator orgs | Yes |
| A-03 | Generator is paid on collected kg, not accepted kg | Collected kg; the collector bears rejection risk |
| A-04 | No clawback from the generator on full rejection | No clawback |
| A-05 | Platform fee 1–3% [ILLUSTRATIVE] | Configurable |
| A-06 | Payments are simulated in the MVP | Ledger only |
| A-07 | Weighing tolerance 2% between pickup and receipt | 2% |
| A-08 | Pickup/estimate tolerance 20% | 20% |
| A-09 | The recycler, as certificate holder, creates allocations | Yes |
| A-10 | Per-batch share of a combined run is pro rata by input kg (informational) | Pro rata |
| A-11 | NGO fee is per period, not per decision | Per period |
| A-12 | One NGO per batch (round-robin among in-scope NGOs) | Round-robin |
| A-13 | Sampling policy for NGO review | 100% for the MVP; sampling P1 |
| A-14 | Batches in a consignment are weighed individually at receipt | Individual |
| A-15 | Default expected rejection/loss when history is missing | Per-material defaults in `pricing_assumptions` (e.g. 10% rejection, 10% loss, [ILLUSTRATIVE]) |
| A-16 | Mass-balance flag threshold | 3% of input |
| A-17 | Minimum history for showing indicators | n ≥ 5 (limited), n ≥ 20 (sufficient) |
| A-18 | Forecast method | Trailing 8-week mean × seasonal factor |

## 6. Open questions requiring human or legal validation
| ID | Question |
|---|---|
| Q-01 | What is the latest consolidated text of the PWM Rules and the EPR guidelines, including any 2025–2026 amendments? |
| Q-02 | Confirm the official URLs and the exact clause citations for every [REG] statement in 08 |
| Q-03 | Which records must a PWP keep per certificate, and for how long? |
| Q-04 | Does CPCB offer any authorised API or bulk verification for certificate numbers? (Assumed: none) |
| Q-05 | Can contracts or declarations make off-platform double use of a recycler's quantities enforceable? |
| Q-06 | Do current rules give NGOs or third-party auditors any defined role (e.g. audits under the EPR guidelines)? |
| Q-07 | Is per-batch attribution of a combined run acceptable to PIBO auditors, or is certificate-level attribution enough? |
| Q-08 | Which DPDP Act rules are in force, and what is the lawful retention basis for custody records? |
| Q-09 | GST and TDS treatment of payments to households and collectors |
| Q-10 | Are any licences or registrations required for collectors/aggregators in Mumbai (MPCB/BMC)? |
| Q-11 | How should packaging categories be mapped when a recycler processes mixed category inputs? |
| Q-12 | Is end-of-life processing (co-processing, WtE) in scope for ReLoop allocations? Default: record it, label it separately |
| Q-13 | Should generators see their own performance indicators? Default: yes |
| Q-14 | How should batches be handled when only a combined consignment weight is available at receipt? Default: not permitted in the MVP |
